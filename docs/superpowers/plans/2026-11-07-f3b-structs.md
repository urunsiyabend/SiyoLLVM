# F3b — Structs, `impl` methods, enums Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Compile struct declarations, struct literals, field reads and writes (nested, compound, through parameters and array elements), `impl` methods (with `self`) and static constructors such as `Point.new(...)`, and integer-backed enums, all with JVM-exact output.

**Architecture:** A struct value is a heap object `SiyoStruct {tag 7, type name, field count, field names, field values}`. Field values are `any` values, as in the reference's `SiyoObject extends LinkedHashMap<String,Object>`. Fields are kept in the order in which the literal wrote them, which is the order `toString` prints. The bound member nodes carry no struct identity, so field access looks the field up by name at run time: the IR passes a pointer to an interned field-name constant, and the runtime compares pointers first and bytes second. Static types coerce through F2's boxing and checked casts. `impl` methods are ordinary functions whose first parameter is `self`. Enum members are `int` constants. `Frontend` stops rejecting struct, enum and impl declarations before binding. Interfaces, sum types and actors stay rejected.

**Tech Stack:** Java 21, Maven, JUnit 5, C11 runtime, clang ≥ 15.

**Spec:** `docs/superpowers/specs/2026-11-07-native-toolchain-design.md` (§2, F3). Frontend facts: `docs/superpowers/specs/2026-11-07-frontend-survey.md` §4 "Struct-related nodes", "Impl methods" and §5.

## Global Constraints

- Reference semantics: `siyoc run` 0.9.0 (`02c226298296fb4379f7251a9dfba19b7e887f3d`). Every corpus expectation comes from `scripts/reference-oracle.sh run`, run through `bounded.py`.
- Probed (to be re-verified by the oracle):
  - `toString` of a struct is `Name { f: v, g: w }` in literal order.
  - Structs alias: assignment and passing share one object.
  - A method mutating `self` is visible to the caller.
  - Enum members print as ints and take part in arithmetic.
  - `typeName(p)` gives `Point`.
- Memory is never freed. Runtime errors raise catchable Java exceptions (F2), and every raising runtime function is classified in `RuntimeIr.RAISING` (`RuntimeIrTest`).
- Constructs the reference rejects or cannot verify are rejected at compile time with a clear `[llvm] … not supported` diagnostic. This covers interfaces, sum types, `match`, actors, closures stored in fields and the reflection builtins other than `typeName`, unless a task adds them.
- `upstream/` is never edited. IR names stay index-based. The runtime C compiles warning-free.
- Host rule: plain `mvn` is the bounded wrapper; the oracle, clang and built binaries run through `python3 ~/.hermes/automation/siyollvm/bounded.py --`.

## Review Focus

- **Aliasing.** Cover each of these:
  - two variables sharing one struct;
  - a struct passed to a function that mutates a field;
  - a struct stored in an array and in another struct's field, then mutated through each path;
  - `b.p.x = 99` changing the value that `r` also names.

  Test `struct_aliasing` (Task 1).
- **Field order and printing.** Cover each of these:
  - literal order differing from declaration order;
  - nested structs, arrays of structs and structs holding arrays;
  - a struct printed through `any`.

  Test `struct_print` (Task 1).
- **Typed field reads at erased sites.** Cover:
  - `int`, `long`, `bool`, `string` and array fields;
  - compound assignment `p.x += 1`, where the reference evaluates the target twice;
  - a null field read into `int`, which raises an NPE.

  Test `struct_fields` (Task 1).
- **Methods.**
  - **Calls:** a method calling another method on `self`; a recursive method; a static `new` building a struct with a literal; a method called on an array element (`ps[0].show()`).
  - **Exceptions:** a method that throws, caught by its caller.

  Test `struct_methods` (Task 2).
- **Enums.**
  - **Values:** explicit and implicit values (`A = 10, B` makes `B` 11); negative values; enum members in comparisons and in `if`/`while`; enum values stored in arrays and struct fields.

  Test `enums` (Task 2).

### Task 1: Struct values and fields

**Files:**
- Modify: `src/main/java/siyollvm/frontend/Frontend.java` (stop rejecting `StructDeclaration` before binding), `SubsetValidator.java`, `IrEmitter.java`, `LlvmTypes.java`, `RuntimeIr.java`, `siyo_rt.{c,h}`
- Test: `FrontendTest`, `SubsetValidatorTest`, `IrEmitterTest`, `RuntimeIrTest`; corpus cases `struct_basic`, `struct_aliasing`, `struct_print`, `struct_fields`, `struct_null_field` (each with oracle expectations)

**Interfaces:**
- **C structs.** `typedef struct SiyoStruct { uint32_t tag; int32_t count; const SiyoStr *type_name; const SiyoStr **names; void **values; } SiyoStruct;` with `SIYO_TAG_STRUCT = 7`.
- **C functions.**
  - `SiyoStruct *siyo_rt_struct_new(const SiyoStr *type_name, int32_t count, const SiyoStr **names)` creates a struct with all values null. Names are in literal order.
  - `void *siyo_rt_struct_get(SiyoStruct*, const SiyoStr *name)` and `void siyo_rt_struct_set(SiyoStruct*, const SiyoStr *name, void *value)` look up the field by name. On a null receiver they raise `java.lang.NullPointerException`. Setting a field the literal did not write appends it, as in `LinkedHashMap.put`.
  - `void *siyo_rt_cast_struct(const void*)` is the checked cast from `any`.
- **Shared behaviour.** `siyo_rt_any_to_string` renders structs. `siyo_rt_any_equals` compares structs as maps, ignoring the type name, as the survey records for `Objects.equals` on two `SiyoObject`s. The oracle confirms this.
- **Java side.**
  - `LlvmTypes.of(SiyoStruct.class)` is `ptr`.
  - The validator accepts `BoundStructLiteralExpression`, `BoundMemberAccessExpression` and `BoundMemberAssignmentExpression` whose target is a struct, and `SiyoStruct` as a variable, parameter, return, element and field type.
  - The struct declaration's placeholder statement emits nothing.

### Task 2: `impl` methods and enums

**Files:** `Frontend.java` (stop rejecting `ImplDeclaration` and `EnumDeclaration`), `SubsetValidator.java`, `IrEmitter.java`; corpus `struct_methods`, `struct_method_throw`, `enums`, `enum_values`.

**Interfaces:**
- **Impl methods.** These are `FunctionSymbol("Point.isPost", [self: SiyoStruct, …])`, and calls arrive as plain `BoundCallExpression`s with `self` as the first argument. The validator accepts them like user functions, keyed by identity. Their bodies come from the bound scope; check whether the binder lowers them already, per survey §1 ("impl-method bodies are already lowered"). Lowering an already-lowered body twice must be avoided or proven harmless.
- **Enums.** Find how the binder represents `Color.Green`: a literal, or a member access on an enum symbol. Emit an `i32` constant, and reject anything else about enums explicitly.
