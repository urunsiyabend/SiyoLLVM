# F5 — `projects/ledger` application Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `projects/ledger`, a multi-module Siyo command-line application that reconciles a CSV of transactions into a report. It must build natively with SiyoLLVM from a fresh clone, with no SiyoCompiler checkout and no JVM in the executable. Every fixture's output must be checked against two independent oracles: the JVM reference `siyoc run` on the same sources, and a Python implementation written only from `projects/ledger/FORMAT.md`.

**Architecture:**
- The behaviour contract is `projects/ledger/FORMAT.md`. It supersedes the design spec's early sketch, which used `amount_cents`.
- **Sources** (`projects/ledger/src/`):
  - `main.siyo`: arguments, orchestration, exit status;
  - `csv.siyo`: line-to-fields state machine;
  - `model.siyo`: `Transaction` and `Rejection` structs, validation;
  - `ledger.siyo`: aggregation into maps of structs;
  - `report.siyo`: sorting, money formatting, padding, report text.
- **Fixtures** are in `projects/ledger/tests/<case>/`:
  - `args` holds one argument per line. The paths in it are relative to the case's run directory.
  - `files/` holds the inputs.
  - Expected outputs: `expected.stdout`, `expected.stderr` (first line), `expected.exit`, and `expected.report` when a report is written.
- **Oracles.** The expected files are generated by running the JVM reference on the same sources from a scratch copy of the case. Python oracle `projects/ledger/oracle/ledger.py` is written by a different implementer who sees only FORMAT.md and the fixtures. A check compares the Python output to the committed expected files.
- **Native gate.** The native gate builds the application through the real CLI path and runs every case in a fresh directory.

**Tech Stack:** Siyo (SiyoLLVM subset), Java 21/JUnit 5 harness, Python 3 (oracle, standard library only), clang ≥ 15.

**Spec:** `docs/superpowers/specs/2026-11-07-native-toolchain-design.md` ("Application target"), `projects/ledger/FORMAT.md` (binding behaviour), `docs/DEVELOPMENT_GOAL.md` (milestone completion).

## Global Constraints

- The application uses only what `docs/SUBSET.md` accepts. Where the subset forces a workaround, note it in a comment in the source. Known workarounds:
  - Bind elements of cross-module array returns to a typed variable before using them, because they are `any`.
  - Use the method forms `m.has(k)` and `m.keys()` on maps.
  - Do not use a function named `fields`.
  - Sorting is hand-written: there are no lambdas, so the `sort` builtin is unavailable.
- Amounts are `long` cents. There are no floats.
- **Determinism.** Outputs are fully determined by FORMAT.md and the inputs: sorting is total, and there is no time, randomness or environment dependence. Fixtures are valid UTF-8.
- **Fixture coverage:**
  - clean
  - mixed rejections, covering every reason
  - quoting (`""`, commas in quotes, unterminated, malformed)
  - Unicode accounts, categories and memos (Turkish, CJK, emoji), including sorting across the BMP/supplementary boundary
  - CRLF and lone-CR line endings, and blank lines
  - an empty file, a header-only file and a bad header
  - a missing input file
  - an unwritable report path
  - the usage error
  - one large input of at least 5 000 rows. It is generated by a committed deterministic generator script; the generated file is committed too.
- **Host rule:** plain `mvn` is the bounded wrapper. The JVM oracle, the Python oracle, clang and built executables run through `python3 ~/.hermes/automation/siyollvm/bounded.py --` when run by hand. Tests run inside the bounded Maven scope.
- The native gate fails, never skips, when clang or `python3` is missing.

## Review Focus

- **Python oracle independence.**
  - It must not be derived from the Siyo sources: the Task 2 implementer must not read `projects/ledger/src/`.
  - It must implement UTF-16 lengths and ordering. Python's `len` and `<` count and order by code point, so they are wrong for emoji.
  - It must reproduce Java `readLine` splitting.

  Test: oracle agreement on the `unicode` and `line_endings` cases (Task 2).
- **Exit status and stream separation on every error path.** Each error must produce only stderr, no report file, and exit 2. A rejection-only run must exit 3 with the report written.

  Test: cases `missing_input`, `unwritable_report`, `usage`, `bad_header` (Task 1).
- **Large input under never-free memory.** Record the peak RSS and wall time of the native run on the large fixture through the bounded helper, and document them.

  Test: case `large`, plus measured numbers in `docs/evidence/f5-ledger/` (Task 3).
- **Fresh clone.** Clone the pushed head into scratch and run both gates there through the bounded `mvn`. The clone must have no sibling SiyoCompiler checkout on the path.

  Task 3.

### Task 1: Application, fixtures, JVM-oracle expectations, native gate

**Files:**
- Create:
  - `projects/ledger/src/{main,csv,model,ledger,report}.siyo`
  - `projects/ledger/README.md` (usage, build command, module map, limits)
  - `projects/ledger/tests/<case>/…`
  - `projects/ledger/tools/gen_large.py` (deterministic, fixed seed, standard library only)
  - `projects/ledger/tools/oracle-jvm.sh`. It runs `scripts/reference-oracle.sh`-style JVM runs per case in a scratch copy and writes the `expected.*` files, including the report file.
  - `src/test/java/siyollvm/nativegate/LedgerAppNativeTest.java`
- Modify: `pom.xml`, only if the test needs the `projects/` path as a resource. Prefer reading it through `TestPaths.projectDir()`.

**Interfaces:**
- `LedgerAppNativeTest` builds `projects/ledger/src/main.siyo` once with `Compiler`/`Clang`, the same path as `bin/siyollvm build`. For each case it copies `files/` to a fresh run directory, runs with the `args` under `LC_ALL=C`, and compares stdout, stderr, exit status and the report file byte for byte. When a case expects no report, the test asserts the report file does not exist.
- When `expected.exit` is 2, the expected stdout must be empty.

### Task 2: Independent Python oracle

**Files:**
- Create: `projects/ledger/oracle/ledger.py` (standard library only), `projects/ledger/oracle/README.md`, `src/test/java/siyollvm/nativegate/LedgerOracleNativeTest.java`.
- The oracle implementer reads only `projects/ledger/FORMAT.md` and `projects/ledger/tests/`. They must not open `projects/ledger/src/` and must not read the JVM outputs before writing the oracle.

**Interfaces:**
- `python3 oracle/ledger.py <csv> <report>` implements FORMAT.md fully: errors, exit status and both output streams. The I/O error `<message>` reproduces Java's `<path> (<strerror>)` form.
- `LedgerOracleNativeTest` runs the oracle on every case in a fresh directory and asserts byte equality with the committed `expected.*` files. It runs in the native profile and fails when `python3` is missing.

- [ ] **Step 1:** Write the oracle from FORMAT.md.
- [ ] **Step 2:** Write the agreement test.
- [ ] **Step 3:** Any disagreement is investigated against FORMAT.md and reported. Neither side's expected files may be edited to make the oracles agree. A FORMAT.md ambiguity is escalated to the controller, who rules on it and regenerates from the reference.
- [ ] **Step 4:** Commit `test: independent Python oracle for projects/ledger`.
