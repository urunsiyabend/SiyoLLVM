# F3a — Arrays, `for … in`, `range`, `split` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Compile Siyo arrays (`T[]`, `Array<T>`) with JVM-exact semantics: literals, indexing, index assignment, `len`/`push`/`pop`/`removeAt`, `toString`, `for … in` over arrays and `range`, `split`, and string indexing.

**Architecture:** An array is a heap object `SiyoArray {tag 5, len, cap, items}` whose items are `any` values (tagged pointers; primitives boxed, as in a Java `ArrayList<Object>`). A static element type comes from the bound node (`BoundIndexExpression.getClassType()`, `BoundArrayLiteralExpression.getElementType()`); reads unbox through F2's checked casts, writes box through `IrEmitter.coerce`. Bounds errors raise catchable Java exceptions through F2's pending mechanism. `for … in` needs no lowering of its own: the binder already desugars it into an index loop over `len`.

**Tech Stack:** Java 21, Maven, JUnit 5, C11 runtime, clang ≥ 15.

**Spec:** `docs/superpowers/specs/2026-11-07-native-toolchain-design.md` (§2, §3, §4, F3). Frontend facts: `docs/superpowers/specs/2026-11-07-frontend-survey.md` §4 "Arrays and maps", "For-in", §5 "Arrays and strings".

## Global Constraints

- Reference semantics: `siyoc run` 0.9.0 (`02c226298296fb4379f7251a9dfba19b7e887f3d`); every corpus expectation from `scripts/reference-oracle.sh run` (run through `bounded.py`); stderr expectation = JVM first line.
- Memory is never freed; arrays grow by doubling; boxed ints in −128..127 come from a static cache (no allocation), like Java's `Integer` cache.
- Runtime errors raise through `siyo_rt_raise_java` and are catchable (F2); every raising runtime function is classified in `RuntimeIr.RAISING` (enforced by `RuntimeIrTest`).
- Constructs the reference rejects or fails to verify are rejected at compile time, never given an invented meaning.
- The snapshot under `upstream/` is never edited. Index-based IR names only. Runtime C warning-free (`RuntimeBuildNativeTest`).
- Host rule: plain `mvn` is a 768 MiB bounded wrapper; oracle, clang and binaries run through `python3 ~/.hermes/automation/siyollvm/bounded.py --`. Corpus programs stay modest (≤ 10^5 elements).

## Review Focus

- Aliasing: two variables naming one array, an array stored inside another and mutated through either name; `push` inside a `for … in` over the same array (the loop re-reads `len`) — test `array_aliasing` (Task 1) and `for_in_mutation` (Task 2).
- Bounds: index `-1`, `len`, `pop`/`removeAt` on empty, `removeAt(xs, len)`, index assignment out of range — each caught and uncaught — test `array_bounds` (Task 1).
- Erased reads: an element read at type `Object` (`any[]`), unboxed into `int` with a wrong tag (CCE), `null` element into `int` (NPE) — test `array_any_elements` (Task 1).
- `split` edges: empty input, empty delimiter, trailing/leading delimiters, multi-character delimiter, non-ASCII and embedded NUL — test `split_edges` (Task 2), checking `len` as well as printed form (`[""]` and `[]` print alike).
- Large `range` (10^5) inside `for … in`: finishes under the run timeout within the 768 MiB cap — test `range_large` (Task 2).

**Interfaces:**
- C: `typedef struct SiyoArray { uint32_t tag; int32_t len; int32_t cap; void **items; } SiyoArray;` (`SIYO_TAG_ARRAY = 5`); `SiyoArray *siyo_rt_array_new(int32_t capacity)`; `void siyo_rt_array_push(SiyoArray*, void *value)`; `void *siyo_rt_array_get(SiyoArray*, int32_t index)` and `void siyo_rt_array_set(SiyoArray*, int32_t index, void *value)` (out of range: `java.lang.IndexOutOfBoundsException: Index I out of bounds for length L`, exact wording from the oracle); `void *siyo_rt_array_pop(SiyoArray*)`; `void siyo_rt_array_remove_at(SiyoArray*, int32_t)`; `int32_t siyo_rt_array_len(SiyoArray*)`; null receiver → `java.lang.NullPointerException` (deviation wording as F1). `siyo_rt_any_to_string` renders arrays as Java's `AbstractCollection.toString` (`[a, b]`, elements via `String.valueOf`, nested arrays recursive); `siyo_rt_any_equals` compares arrays element-wise (`List.equals`). `void *siyo_rt_cast_array(const void*)` — checked cast from `any` with the JVM's CCE message.
- Java: `LlvmTypes.of(SiyoArray.class)` = `ptr`. The validator accepts `SiyoArray` as variable, parameter, return and element type; `BoundArrayLiteralExpression`; `BoundIndexExpression` on arrays (strings in Task 2); `BoundIndexAssignmentExpression`; builtins `LEN` on arrays, `PUSH`, `POP`, `REMOVE_AT`; `toString`/`print`/`println` of arrays; arrays in `+` with a string only where the binder allows it (`any` operand).
- Static element types: element reads coerce from `Object` to the node's class type with F2's checked casts; writes and `push` coerce the value to `Object` (boxing).
- Boxing cache: `siyo_rt_box_int` returns a static box for −128..127.

### Task 2: `for … in`, `range`, `split`, string indexing

**Files:** same Java/C files; corpus `for_in_arrays`, `for_in_mutation`, `range_basic`, `range_large`, `split_edges`, `string_index` (+ oracle expectations).

**Interfaces:**
- `for x in arr` and `for i in range(a, b)` compile through the binder's desugaring (block with `_colN`, `_idxN`, `len`, `BoundIndexExpression`); the validator accepts the desugared `BoundForStatement`/variables it produces. `for` over maps, sets, channels or `any` stays rejected (maps arrive in F3c).
- C: `SiyoArray *siyo_rt_range(int32_t from, int32_t to)` (Java `range` semantics incl. `from > to` — take from the oracle); `SiyoArray *siyo_rt_str_split(const SiyoStr*, const SiyoStr *delim)` — literal (not regex) split with limit −1: trailing empty strings kept, empty delimiter splits into UTF-16 units (pin the exact JVM result, incl. trailing `""`, with `len`), empty input → oracle-defined; `SiyoStr *siyo_rt_str_char_at(const SiyoStr*, int32_t)` for `s[i]` (one UTF-16 unit; out of range raises the JVM's `StringIndexOutOfBoundsException` wording).

- [ ] **Step 1:** Validator tests (for-in over arrays and `range` accepted; over `any`/maps rejected).
