# F4 — Modules and native standard library Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Compile multi-file Siyo programs (`import "x"`, `import "dir/x"`, `import "x" as y`) with the reference's resolution, cross-module functions, globals, structs, enums and `impl` methods, and dependency-first initialisation. Provide `std/io`, `std/os` and `std/strings` natively.

**Architecture:**
- **Binding.** The snapshot binder resolves and binds imports itself (`ModuleHandler`) when it is given the absolute source path. `Frontend` keeps the `ModuleRegistry` and turns the result into one lowered program made of several units:
  - every module's own functions (bodies from `ModuleSymbol.getFunctionBodies()`, lowered where the binder left them unlowered);
  - every module's lowered top-level block, run before its `init()`;
  - the main file's functions, globals, `init` and `main`.
- **Symbol mapping.** An importer reaches module members through *qualified* symbols (`util.twice`, `util.calls`). The emitter maps each qualified symbol to the module's own symbol:
  - functions by (owner class name, JVM method name, arity), as in survey §1;
  - variables by (owner class, field name).

  All symbol-keyed maps become identity maps. `FunctionSymbol.equals` ignores scope, so two modules' `fn helper()` would otherwise collide.
- **Diagnostics.** Each unit carries its own file name and `SourceText`, so a diagnostic inside a module names that module's file.
- **Standard library.** SiyoLLVM ships its own `std/io.siyo`, `std/os.siyo` and `std/strings.siyo` as jar resources. The binder loads them as `classpath:std/x.siyo`.
  - `std/io` and `std/os` declare their functions with stub bodies. The emitter replaces each one with a call into the C runtime, through an intrinsic table keyed by **(module identity `classpath:std/<name>.siyo`, function name, arity)**. A user file that happens to be named `std/io.siyo` is therefore never substituted.
  - The validator rejects any function of those classpath modules that has no intrinsic, so a stub can never run.
  - `std/strings` is written in plain Siyo and compiled normally.

**Tech Stack:** Java 21, Maven, JUnit 5, C11 runtime (POSIX file APIs), clang ≥ 15.

**Spec:** `docs/superpowers/specs/2026-11-07-native-toolchain-design.md` (§5 Modules, F4). Frontend facts: `docs/superpowers/specs/2026-11-07-frontend-survey.md` §1 (resolution, `ModuleSymbol`, qualified symbols, init order, the bare-filename NPE), §3 (args, std files).

## Global Constraints

- Reference semantics: `siyoc run` 0.9.0 (`02c226298296fb4379f7251a9dfba19b7e887f3d`), run from the program's directory. Every expectation comes from `scripts/reference-oracle.sh` (through `bounded.py`).
- **Probed (re-verify):**
  - Init order is `util init`, then `helper init`, then the main globals, then `main init`. Each module is initialised once, even when imported twice and under an alias, and its state is shared across aliases.
  - `os.args()` excludes the program name.
  - `io.readLines` splits on `\n`, `\r\n` and `\r`. `io.readFile` joins lines with `\n` and drops the final newline (`"a\r\nb\nc\n"` reads back as 5 UTF-16 units).
  - A missing file raises `java.io.FileNotFoundException`, and its caught payload is `missing.txt (No such file or directory)`.
  - `io.eprintln` writes a line to stderr.
  - `os.exit(n)` exits with status `n`.
  - `strings.join`, `padLeft` and `repeat` behave as shown in the probe.
- No sibling SiyoCompiler checkout and no JVM at run time. The std sources SiyoLLVM ships are its own files, written for SiyoLLVM; the snapshot is not edited.
- Memory is never freed. Runtime errors raise catchable Java-shaped exceptions (F2). Every raising runtime function is in `RuntimeIr.RAISING` (`RuntimeIrTest`).
- Host rule: plain `mvn` is the bounded wrapper. The oracle, clang and binaries run through `python3 ~/.hermes/automation/siyollvm/bounded.py --`. Tests that write files do so in a fresh copy of the case directory under the build's temp root, never in the source tree.

## Review Focus

- **Two modules each defining `fn helper()`** with the same arity, plus a main-file `helper`. Each call must reach its own module's function, and each module's globals must stay separate. Test `modules_same_names` (Task 1).
- **Diamond imports** (A imports B and C, both import D; D has state and an `init`). D must initialise exactly once, first. An alias and a plain import of the same module must share one state. Test `modules_diamond` (Task 1).
- **Errors inside module code.** A compile error in an imported file reports `lib/util.siyo(line, col)`. A runtime error inside a module function is catchable by the importer. An uncaught error in a module's `init()` aborts before `main` runs. Tests `modules_errors` (Task 1) and `FrontendTest`.
- **File I/O edge cases:**
  - Unicode file names; CRLF, CR-only and missing final newline; an empty file.
  - Invalid UTF-8 bytes (Java replaces them with U+FFFD); a directory passed to `readFile`; a read-only path.
  - `writeFile` overwriting an existing file, and `appendFile`.

  Test `stdio_files` (Task 2), with expectations from the oracle run in a copy of the fixture directory.
- **Program arguments:** none; Unicode; an empty-string argument; arguments with spaces. `os.exit` inside a `try`, which must still exit, with stdout flushed. Test `stdos_args` (Task 2).

### Task 2: Native `std/io`, `std/os`, `std/strings`

**Files:**
- Create: `src/main/resources/std/io.siyo`, `std/os.siyo`, `std/strings.siyo`. Use the same public signatures as SiyoCompiler 0.9.0's std (survey §3). Bodies are stubs for io/os; strings is real Siyo.
- Modify: `siyo_rt.{c,h}`, `RuntimeIr.java`, `IrEmitter.java` (intrinsic table), `SubsetValidator.java`
- Harness: support `main.args` (one argument per line, UTF-8) and a `files/` fixture directory that is copied into the run directory. The test runner and `reference-oracle.sh` both run the program in a fresh copy of the case directory, with the arguments passed.
- Corpus: `stdio_files`, `stdio_errors`, `stdos_args`, `stdos_exit`, `stdstrings`

**Interfaces:**
- **`std/io` intrinsics:** `readFile`, `readLines`, `writeFile`, `appendFile`, `exists`, `isFile`, `isDir`, `eprintln`, `mkdir`, `delete`, `listDir`.
  - Java semantics: UTF-8 decoding with U+FFFD replacement for invalid bytes; `readLine` splitting; FileWriter UTF-8 encoding, where a lone surrogate is written as `?`.
  - I/O errors raise `java.io.FileNotFoundException` / `java.io.IOException` with Java's message, `<path> (<strerror text>)`; take exact wording from the oracle.
  - `listDir` order: take it from the reference (`File.list()` order is unspecified). If it is not deterministic, sort, or reject `listDir` and document it.
- **`std/os` intrinsics:** `args() -> string[]` (argv[1..]), `exit(code)` (flush stdout and stderr, then exit), `env(name) -> string` (`""` when unset), `cwd() -> string`.
- **`std/strings`:** `join`, `repeat`, `padLeft`, `padRight`, `trimStart`, `trimEnd`, `lastIndexOf`, `chars`, `lines`, `isInt`, written in Siyo to match the reference's results. `builder()` is rejected.
- **Validator:** a call into a classpath std module function with no intrinsic and no compiled body is rejected (`std/io.<fn>() is not supported by SiyoLLVM`).
