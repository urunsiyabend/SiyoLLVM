# F3c — Maps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Compile Siyo maps (`Map<K, V>`, `map`, `{…}` literals, `map()`) with the JVM reference's exact `LinkedHashMap` semantics: index read/write, `has`/`get`/`set`/`remove`/`keys`/`size`, `len`, `for k in m`, `toString`, equality.

**Architecture:**
- **Representation:** a map is a heap object `SiyoMap {tag 6, …}`, an insertion-ordered hash table whose keys and values are `any` values.
  - Equality uses `siyo_rt_any_equals`, so `Integer` 1 and `Long` 1 are different keys, as in Java.
  - The hash is computed from the same value classes.
  - Overwriting a key keeps its position. Removing a key and inserting it again appends it at the end.
  - Iteration order is insertion order.
- **Method calls:** the binder binds `m.has(k)` and the other map methods as `BoundJavaMethodCallExpression` on the `SiyoMap` class, per survey §4. The validator accepts exactly the listed method names on a `SiyoMap` target, and the emitter maps them to runtime calls. Every other Java method call stays rejected.
- **Iteration:** `for k in m` arrives as the binder's desugaring over `$mapKeys(m)` (`BuiltinFunctions.MAP_KEYS`), which returns a key array; F3a's index loop does the rest.

**Tech Stack:** Java 21, Maven, JUnit 5, C11 runtime, clang ≥ 15.

**Spec:** `docs/superpowers/specs/2026-11-07-native-toolchain-design.md` (§2, F3). Frontend facts: `docs/superpowers/specs/2026-11-07-frontend-survey.md` §4 "Arrays and maps", "Impl methods" (map methods bind as Java method calls), "For-in"; §5 "Maps".

## Global Constraints

- **Reference semantics:** `siyoc run` 0.9.0 (`02c226298296fb4379f7251a9dfba19b7e887f3d`). Every corpus expectation comes from `scripts/reference-oracle.sh run`, run through `bounded.py`.
- **Probed behaviour** (the implementer re-verifies each with the oracle):
  - `{b: 3, a: 1}` after `b`, `a`, `b=3`.
  - A missing key reads `null`.
  - `imut v: int = m["nope"]` gives `java.lang.NullPointerException: Cannot invoke "java.lang.Integer.intValue()" because the return value of "codeanalysis.SiyoMap.get(Object)" is null`.
  - `m.keys()` prints `[b, a]`.
  - `Map<int, string>` prints `{5: five, 1: one}`.
  - `map()` creates an empty map.
  - `push(nest["xs"], 3)` mutates the array stored in the map.
- **Memory:** never freed. The table grows by doubling. A removed entry may leave a tombstone, but iteration and `len` must skip it.
- **Errors:** raising runtime functions are classified in `RuntimeIr.RAISING` (`RuntimeIrTest`), and errors are catchable (F2).
- **Rejections:** constructs the reference rejects or cannot verify are rejected with a clear `[llvm] … not supported` diagnostic. This covers sets, map methods outside the accepted list, and maps held in `any` if the reference fails on them.
- **Repository rules:** `upstream/` is never edited. IR names are index-based only. The runtime C must compile warning-free.
- **Host rule:** plain `mvn` is the bounded wrapper. The oracle, clang and built binaries run through `python3 ~/.hermes/automation/siyollvm/bounded.py --`. Corpus programs stay modest (≤ 10^5 entries).

## Review Focus

Task 1 owns all of these.

- **Order:** overwrite keeps position; remove then reinsert appends; iteration after many removes and inserts; growth past several table sizes keeps order. Test `map_order`.
- **Key identity:** `int` and `long` keys with equal values are distinct; string keys that are equal by value but different objects (built by concatenation) match; keys containing NUL or non-ASCII text; a `null` key and `null` values (`has` versus `get` returning null). Test `map_keys`.
- **Aliasing:** two names for one map; a map stored in a struct field or an array, then mutated through each path; arrays and structs stored as values and mutated in place. Test `map_aliasing`.
- **Mutation during `for k in m`:** the reference's `$mapKeys` snapshots the keys, so test what the reference does when the body inserts or removes. Test `map_iteration_mutation`.
- **Typed reads at erased sites:** a missing key into `int` (exact NPE above); a wrong-typed value (CCE); `m[k] += 1` on `Map<string, int>`, the counting idiom the application needs. Test `map_typed_reads`.

### Task 1: Map values, literals, indexing, methods, iteration

**Files:**
- Modify: `src/main/resources/siyollvm/runtime/siyo_rt.{c,h}`, `src/main/java/siyollvm/ir/{IrEmitter,LlvmTypes,RuntimeIr}.java`, `src/main/java/siyollvm/check/SubsetValidator.java`
- Test: `SubsetValidatorTest`, `IrEmitterTest`, `RuntimeIrTest`; corpus `map_basic`, `map_order`, `map_keys`, `map_aliasing`, `map_iteration_mutation`, `map_typed_reads`, `map_missing_int_uncaught` (each with its oracle expectations)

**Interfaces:**
- **C type:** `SiyoMap` with `SIYO_TAG_MAP = 6`. The layout is the implementer's choice; keep it behind functions and `_Static_assert` the tag offset.
- **C functions:**
  - `SiyoMap *siyo_rt_map_new(void)`
  - `void *siyo_rt_map_get(SiyoMap*, void *key)`: returns null when the key is absent.
  - `void siyo_rt_map_put(SiyoMap*, void *key, void *value)`
  - `_Bool siyo_rt_map_has(SiyoMap*, void *key)`
  - `void *siyo_rt_map_remove(SiyoMap*, void *key)`: use the reference's return value if one is observable.
  - `int32_t siyo_rt_map_size(SiyoMap*)`
  - `SiyoArray *siyo_rt_map_keys(SiyoMap*)`: a fresh array in insertion order.
  - On a null receiver, each function raises `java.lang.NullPointerException`, using the deviation wording from F1–F3b.
- **Runtime extensions:**
  - `siyo_rt_any_to_string` renders maps as `{k: v, k2: v2}`.
  - `siyo_rt_any_equals` compares maps with `AbstractMap.equals` semantics.
  - `siyo_rt_cast_map` is the checked cast from `any`, with the JVM CCE message.
  - A hash function covers every tag: string by content; boxed int, long and bool by value; arrays, maps and structs by identity or content, whichever matches the reference's `hashCode`/`equals` pairing.
- **Validator** accepts:
  - `SiyoMap` as a variable, parameter, return, element, field and value type
  - `BoundMapLiteralExpression`
  - `BoundIndexExpression` and `BoundIndexAssignmentExpression` on a map
  - the builtins `NEW_MAP` (`map()`), `LEN` on a map, and `MAP_KEYS` (for-in)
  - `BoundJavaMethodCallExpression` on a `SiyoMap` target for the methods `get`, `set`, `has`, `remove`, `keys` and `size`, after confirming each name and its result type against the pinned `SiyoMap.java` in the snapshot
  - `toString`, `print` and `println` of maps

  Anything else on a map, including the `SiyoMap` methods not listed, is reported as `map method <name>() is` with the not-supported suffix.
- **Emitter:** keys and values coerce to `Object` (boxing). Reads coerce from `Object` to the node's class type through the checked casts. For the missing-key unbox, use a dedicated unbox that produces the exact `SiyoMap.get(Object)` NPE message, like F3b's field unbox.
